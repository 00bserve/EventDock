# Windows 11 桌面悬浮事件记录工具 — 开发需求说明

## 一、项目定位

开发一款运行于 Windows 11 的轻量级桌面事件记录工具，暂定名称为 **EventDock（事件坞）**。

它不是传统的待办事项软件，也不是复杂的知识库，而是一个始终存在于屏幕边缘、随时可以唤醒的个人事件记录工具。

主要用于记录：

- 日常工作事件
- 项目沟通与客户反馈
- 系统异常及问题截图
- 临时想法与灵感
- 重要事项及处理过程
- 日常生活中的事件

核心设计理念：

**平时不打扰，需要时立即出现，记录后自动沉淀。**

用户不需要频繁打开主程序，也不需要为了记录一件小事建立文档或进入复杂的管理页面。

## 二、技术栈建议

采用适合 Windows 桌面应用的技术方案：

| 技术 | 用途 |
|---|---|
| Electron | 桌面应用运行框架 |
| Vue 3 | 前端界面 |
| TypeScript | 类型管理及业务逻辑 |
| Vite | 项目构建 |
| Pinia | 全局状态管理 |
| Tiptap | 富文本图文编辑器 |
| SQLite | 本地数据持久化 |
| Lucide Icons | 统一线性图标 |
| electron-builder | Windows 安装包及便携版构建 |

采用 Electron 主进程、预加载脚本、渲染进程分离的架构。

所有数据默认保存在本地，无须注册、登录或连接服务器。

## 三、核心交互设计

整个应用划分为四个主要界面：

1. 屏幕贴边悬浮入口
2. 今日事件悬浮面板
3. 事件详情及编辑窗口
4. 历史事件管理窗口

其中，前三个界面是用户日常使用的核心。

### 3.1 屏幕贴边悬浮入口

程序启动后默认不显示主窗口，而是在屏幕右侧边缘显示一个小型悬浮入口。

**视觉设计：**

- 默认贴合屏幕右侧边缘。
- 采用半透明毛玻璃材质。
- 左侧为圆角，右侧紧贴屏幕边缘。
- 显示简洁的日历或事件图标。
- 纵向显示“今日事件”文字。
- 底部显示今日事件数量。
- 具有轻微阴影及半透明白色描边。
- 不使用过于醒目的颜色或持续闪烁动画。

**建议尺寸：**

- 宽度：32～44 DIP
- 高度：140～180 DIP
- 圆角：16～20 DIP
- 默认位置：屏幕右侧垂直居中

**交互要求：**

- 鼠标悬停约 200ms 后，向屏幕内部展开今日事件面板。
- 鼠标移出悬浮入口及事件面板区域后，延迟约 400ms 自动收起。
- 支持点击入口主动展开或关闭面板。
- 支持上下拖动，调整贴边位置。
- 支持吸附至屏幕左侧或右侧。
- 自动记忆上一次停靠位置。
- 支持多显示器及不同 DPI 缩放比例。
- 展开时不应抢占当前正在操作的软件焦点。
- 默认不在 Windows 任务栏显示独立窗口图标。

悬浮入口应始终可用，但尽可能减少对正常工作区域的遮挡。

### 3.2 今日事件悬浮面板

鼠标悬停于贴边入口后，在入口内侧通过平滑动画展开事件面板。

默认情况下只展示当天记录的事件。

**面板顶部：**

- 今日
- 全部
- 归档
- 固定面板按钮
- 搜索按钮
- 更多操作按钮

**事件列表区域：**

每条事件仅展示以下信息：

- 记录时间
- 事件标题
- 事件类型或附件提示图标（可选）

示例：

```text
今日事件                       5

09:10   客户反馈：3D模型穿模
10:30   NV200 联调记录
13:40   临时灵感：问题追踪面板
15:20   系统异常截图
17:50   周会待办

＋ 新建事件
```

列表中不展示正文、图片缩略图及大量标签，保持信息密度和视觉简洁性。

**交互要求：**

- 鼠标悬停事件时，该条目出现浅蓝色背景及轻微描边。
- 点击事件后打开独立的详情窗口。
- 已选中的事件左侧显示蓝色高亮指示条。
- 双击事件可直接进入编辑状态。
- 右键事件可进行编辑、复制、置顶、归档和删除操作。
- 支持按记录时间正序或倒序排列。
- 支持事件列表内部滚动。
- 支持一键新建事件。
- 支持点击固定按钮，使面板保持展开。
- 鼠标在入口、面板及关联详情窗口之间移动时，不应意外触发面板收起。

**建议尺寸：**

- 宽度：320～380 DIP
- 列表单行高度：40～48 DIP
- 圆角：16 DIP
- 内边距：12～16 DIP
- 最大高度：当前显示器可用高度的 75%

面板高度应根据事件数量自动调整。事件较少时，不应出现大面积无意义的空白区域。

### 3.3 事件详情窗口

点击事件列表中的任意事件后，在悬浮面板内侧弹出独立的详情窗口。

以右侧停靠为例，详情窗口显示在事件列表左侧，不遮挡原有列表。

详情窗口包含：

**顶部窗口栏**

- 详情
- 编辑
- 窗口置顶
- 最小化
- 关闭

**事件信息区**

- 事件标题
- 创建时间
- 最后更新时间
- 标签
- 事件状态（可选）

**正文内容区**

支持富文本内容，包括：

- 普通文本
- 标题
- 加粗、斜体、下划线
- 有序列表
- 无序列表
- 待办复选框
- 引用
- 代码块
- 超链接
- 图片
- 简单表格

**图片及附件区**

支持正文内嵌图片，也支持独立附件形式展示。

图片支持：

- Ctrl + V 直接粘贴剪贴板截图
- 拖拽图片文件插入
- 本地文件选择
- 图片缩放
- 点击查看原图
- 复制图片
- 保存图片至本地
- 删除图片

独立附件显示文件名称、文件大小、文件类型及预览图。

**窗口交互：**

- 详情窗口默认以阅读模式打开。
- 点击编辑按钮后切换为编辑模式。
- 编辑内容自动保存，并提供明确的保存状态反馈。
- 窗口支持拖动和调整尺寸。
- 窗口关闭后不影响原始事件。
- 支持窗口独立置顶。
- 用户可以在查看详情的同时继续操作其他软件。
- 详情窗口不得采用阻塞其他应用操作的全局模态弹窗。
- 切换事件时，默认复用当前详情窗口。
- 支持通过右键菜单将不同事件分别打开为独立窗口。

**建议默认尺寸：**

- 宽度：580～720 DIP
- 高度：420～600 DIP
- 圆角：16 DIP
- 正文区域支持独立滚动

窗口位置应根据屏幕剩余空间动态调整，避免超出显示器可用区域。

### 3.4 快速新建事件

快速记录是本应用最重要的能力之一。

提供以下新建方式：

- 点击悬浮面板中的“＋ 新建事件”。
- 通过全局快捷键直接打开新建窗口。
- 通过系统托盘菜单新建。
- 通过可选的悬浮入口右键菜单新建。

新建窗口不需要复杂表单，默认只包含：

- 事件标题
- 正文内容
- 图片及附件
- 标签（可选）

创建时间自动填写为当前系统时间，同时允许手动修改。

标题未填写时，可根据正文首行自动生成标题。

支持以下默认快捷键，且允许用户自定义：

| 快捷键 | 功能 |
|---|---|
| Ctrl + Alt + N | 快速新建事件 |
| Ctrl + Alt + E | 展开或收起事件面板 |
| Ctrl + Alt + F | 搜索历史事件 |
| Ctrl + S | 保存当前事件 |
| Ctrl + V | 粘贴文本或截图 |
| Esc | 关闭当前弹窗 |

新建窗口打开后自动聚焦标题或正文输入框。

支持草稿自动保存，避免误关闭程序导致记录丢失。

## 四、历史事件管理

除悬浮面板外，提供一个独立的历史事件管理窗口。

该窗口主要用于检索、整理和管理历史内容，不作为程序启动时的默认界面。

建议采用三栏布局：

- 左侧：时间范围、标签、归档等分类导航。
- 中间：事件列表。
- 右侧：事件详情及编辑区域。

支持：

- 今日事件
- 昨日事件
- 最近七天
- 最近三十天
- 自定义日期范围
- 全部事件
- 置顶事件
- 已归档事件
- 回收站
- 标签分类
- 全文搜索
- 按日期分组的时间线展示

支持根据标题、正文、标签进行搜索。

事件删除默认进入回收站，避免误操作造成数据永久丢失。

归档事件仍可在历史管理中查看，但默认不再显示于今日悬浮面板。

## 五、UI 视觉设计规范

整体视觉严格参考随需求提交的 Windows 11 毛玻璃风格设计图。

设计方向采用 Fluent Design，结合 Acrylic 毛玻璃材质、半透明背景、细腻描边、轻阴影以及现代圆角设计。

### 5.1 视觉原则

- 简洁、克制、轻量。
- 保持 Windows 11 原生桌面工具的视觉协调性。
- 不采用传统后台管理系统的设计风格。
- 不使用大面积高饱和颜色。
- 不使用夸张的科技发光效果。
- 减少不必要的边框、分隔线和装饰图形。
- 通过留白、字号、透明度和层级表达信息结构。

### 5.2 推荐配色

| 元素 | 参考颜色 |
|---|---|
| 主色 | #2563EB |
| 浅色窗口背景 | #F4F8FC |
| 浅色毛玻璃背景 | rgba(235, 243, 255, 0.82) |
| 主文字 | #172033 |
| 次级文字 | #64748B |
| 普通列表背景 | rgba(255, 255, 255, 0.40) |
| 悬停背景 | rgba(59, 130, 246, 0.10) |
| 选中背景 | rgba(59, 130, 246, 0.16) |
| 选中指示条 | #2563EB |
| 窗口边框 | rgba(255, 255, 255, 0.65) |
| 深色背景 | #20242C |

以上颜色作为初始设计 Token，可根据实际毛玻璃渲染效果调整。

### 5.3 毛玻璃效果

优先实现 Windows 11 原生 Acrylic 或适用的系统级背景材质效果。

不能仅通过 CSS backdrop-filter 模拟真正的桌面背景模糊，因为网页内部模糊与操作系统级窗口背景模糊并不等价。

应根据 Electron 版本及 Windows 系统兼容性选择实现方案。

当原生材质不可用时，自动降级为具有适当透明度或不透明背景的窗口，确保文字可读性。

### 5.4 字体规范

优先使用：

```css
font-family:
  "Segoe UI Variable",
  "Microsoft YaHei UI",
  "PingFang SC",
  sans-serif;
```

| 元素 | 建议字号 |
|---|---|
| 事件详情标题 | 22～24px |
| 面板标题 | 16～18px |
| 列表标题 | 14px |
| 正文内容 | 14px |
| 时间信息 | 12～13px |
| 辅助信息 | 12px |

### 5.5 动画设计

动画应自然、快速，不影响连续操作。

- 悬浮面板展开：向屏幕内侧滑入并淡入。
- 悬浮面板收起：向屏幕边缘滑出并淡出。
- 详情窗口打开：轻微位移及淡入。
- 列表悬停：背景颜色平滑过渡。
- 选中状态：蓝色指示条及浅蓝背景。
- 按钮：轻微透明度变化。

建议动画时长为 150～250ms，使用 ease-out 或类似缓动曲线。

避免明显弹跳、大幅缩放及持续性动画。

### 5.6 主题支持

支持：

- 浅色主题
- 深色主题
- 跟随 Windows 系统主题

同时提供毛玻璃效果开关及适当的透明度调整能力。

默认使用浅色毛玻璃主题。

## 六、本地数据存储

使用 SQLite 管理事件数据，使用独立本地目录保存图片及附件。

不建议将大量图片以 Base64 形式直接写入数据库正文。

### 6.1 事件数据结构

```ts
interface EventRecord {
  id: string
  title: string
  content: string
  eventTime: number
  createdAt: number
  updatedAt: number
  tags: string[]
  isPinned: boolean
  isArchived: boolean
  deletedAt: number | null
}
```

content 字段保存富文本 JSON 的序列化结果。

eventTime 表示事件所属时间，可手动修改，用于今日事件筛选及历史时间线分组。

createdAt 和 updatedAt 分别表示实际创建时间与最后修改时间。

### 6.2 附件数据结构

```ts
interface Attachment {
  id: string
  eventId: string
  fileName: string
  relativePath: string
  mimeType: string
  size: number
  createdAt: number
}
```

### 6.3 数据目录建议

```text
EventDock/
├── data/
│   └── events.db
├── attachments/
│   ├── 2026/
│   │   └── 11/
│   └── thumbnails/
├── backups/
├── config/
└── logs/
```

要求：

- 图片导入后复制至应用数据目录。
- 不依赖原始图片文件的位置。
- 附件路径采用相对于数据根目录的路径。
- 支持数据库及附件整体备份。
- 支持数据目录自定义及安全迁移。
- 支持数据恢复。
- 数据库结构需具备版本迁移能力。
- 支持通过 SQLite FTS5 或其他合适方案实现全文检索，并考虑中文搜索效果。

## 八、桌面端技术实现要求

### 8.1 多窗口架构

建议使用独立的 Electron BrowserWindow 实现不同界面。

```text
Electron Main Process
│
├── DockWindow
│   屏幕贴边悬浮入口
│
├── EventListWindow
│   悬停展开事件面板
│
├── EventDetailWindow
│   事件详情及编辑
│
├── QuickCaptureWindow
│   快速新建事件
│
├── HistoryWindow
│   历史事件管理
│
└── SettingsWindow
    应用设置
```

悬浮入口和列表窗口采用无边框窗口。

由主进程统一负责窗口创建、定位、显示、隐藏、焦点、层级及生命周期管理。

### 8.2 悬停区域管理

贴边入口、事件列表以及关联详情窗口之间应建立统一的交互状态管理机制。

需要处理：

- 鼠标从入口进入列表时不收起。
- 鼠标从列表进入详情窗口时不收起。
- 鼠标短暂经过窗口间隙时不立即关闭。
- 面板固定后不再自动收起。
- 编辑状态下不误关闭详情窗口。
- 鼠标离开关联区域后，按照设置延迟收起未固定面板。

建议使用明确的状态机管理：

```text
COLLAPSED
EXPANDING
EXPANDED
DETAIL_OPEN
PINNED
COLLAPSING
```

避免使用多个相互独立的定时器导致窗口反复展开、闪烁或焦点异常。

### 8.3 窗口与显示器适配

- 根据当前显示器 workArea 计算窗口位置。
- 兼容 Windows 任务栏不同位置。
- 支持 100%、125%、150%、200% DPI 缩放。
- 支持主屏幕及扩展屏幕。
- 支持屏幕分辨率变化后自动重新定位。
- 显示器断开时将窗口迁移至可用屏幕。
- 展开事件面板时不改变当前活动窗口焦点。
- 仅在用户主动编辑或搜索时请求输入焦点。

### 8.4 安全与进程通信

- 开启 contextIsolation。
- 禁用渲染进程 nodeIntegration。
- 通过 preload 暴露受限 API。
- 通过 IPC 完成数据库读写、文件操作及窗口控制。
- 校验 IPC 参数。
- 对富文本内容进行安全处理。
- 限制外部链接及不受信任文件的打开方式。
- 不在渲染进程直接操作本地数据库及文件系统。
- 支持应用单实例运行。

## 九、性能与体验要求

- 程序后台运行时尽可能降低 CPU 占用。
- 避免高频轮询鼠标位置，优先使用事件驱动机制。
- 避免持续刷新或不必要的动画。
- 图片列表及历史事件采用按需加载。
- 大尺寸图片生成缩略图。
- 历史事件数量较多时采用分页或虚拟列表。
- 数据库操作避免长时间阻塞主进程。
- 富文本内容支持防抖自动保存。
- 应用异常退出后能够恢复未完成的草稿。
- 系统休眠恢复及跨午夜后自动刷新今日事件列表。

悬浮入口和今日事件列表应优先保证响应速度，不应等待历史管理窗口加载完成。

## 十、开发阶段划分

### 第一阶段：核心桌面交互验证

优先实现：

- Electron 多窗口基础架构。
- 屏幕右侧贴边悬浮入口。
- 鼠标悬停自动展开。
- 鼠标离开自动收起。
- 今日事件标题列表。
- 点击事件弹出详情。
- Fluent 毛玻璃视觉效果。
- 窗口位置及层级控制。

该阶段使用模拟数据即可。

首先验证核心交互与参考设计图是否一致，不急于实现完整数据管理。

### 第二阶段：事件记录与本地存储

实现：

- 新建、编辑、删除事件。
- Tiptap 富文本编辑器。
- 剪贴板截图粘贴。
- 图片及附件管理。
- SQLite 数据存储。
- 自动保存及草稿恢复。
- 今日事件实时更新。
- 全局快捷键。

### 第三阶段：历史管理与系统集成

实现：

- 历史事件管理窗口。
- 全文搜索。
- 标签管理。
- 归档与回收站。
- 系统托盘。
- 开机启动。
- 深浅色主题。
- 设置管理。
- 数据备份与恢复。
- 多显示器适配。

### 第四阶段：体验优化及交付

完成：

- 窗口闪烁、焦点及收起逻辑优化。
- 动画及视觉细节调整。
- 性能测试。
- 异常恢复测试。
- Windows 11 兼容性测试。
- 安装包及便携版打包。
- 项目 README 和开发文档。

## 十一、核心验收标准

| 场景 | 预期结果 |
|---|---|
| 启动程序 | 仅显示屏幕边缘悬浮入口，不弹出主窗口 |
| 鼠标悬停入口 | 今日事件面板平滑展开，不抢占焦点 |
| 查看事件列表 | 仅显示标题、时间及必要图标 |
| 点击事件 | 在列表内侧打开独立详情窗口 |
| 鼠标跨窗口移动 | 不出现误收起、闪烁或窗口跳动 |
| 鼠标移出面板 | 未固定面板自动收起 |
| 固定面板 | 鼠标移出后仍保持显示 |
| 快捷键新建 | 直接弹出编辑窗口并聚焦输入区域 |
| 粘贴截图 | 截图成功插入正文并持久化 |
| 编辑事件 | 自动保存并同步更新列表 |
| 重启程序 | 数据、附件及窗口设置完整恢复 |
| 切换日期 | 今日事件列表及数量自动更新 |
| 多屏幕操作 | 窗口定位正确，不超出屏幕范围 |
| 关闭窗口 | 程序继续在托盘运行 |
| 网络断开 | 所有核心记录功能仍可正常使用 |

## 十二、开发约束

第一版应严格控制功能范围，不需要实现：

- 用户注册及登录
- 云端同步
- 团队协作
- 在线分享
- 复杂项目管理
- 甘特图
- 复杂任务流程
- AI 内容生成
- 服务端部署

但数据层、窗口层及业务模块应保持合理的解耦，为后续扩展预留空间。

不要将该工具开发成一个需要长期打开的大型管理系统。

## 十三、最终产品目标

希望最终实现的使用体验是：

用户正在正常工作，突然收到一条客户反馈，或者产生一个临时想法。

无需离开当前工作环境，只需通过快捷键打开记录窗口，输入标题、粘贴截图、补充说明，随后关闭窗口继续工作。

需要回顾时，只需将鼠标移动到屏幕边缘，今日发生的事件便会自然展开。

点击任意标题，即可查看完整的图文记录。

当用户不再需要它时，它重新收回屏幕边缘。

整个过程应足够自然、轻量、流畅。

**它应该像 Windows 系统本身的一项能力，而不是一个需要额外管理的软件。**
